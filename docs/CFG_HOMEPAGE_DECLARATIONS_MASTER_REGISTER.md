## 1. Executive summary

### 1.1 What the current `main` homepage actually contains

At the audited main commit, the root homepage is a single static HTML page (`index.html`) supported by `styles.css` and `app.js`. The homepage includes:

1. Cashflow Gate Trading & Markets identity and a DEMO MODE indicator.
2. Virtual practice balance and practice P/L.
3. Illustrative commodity, crypto and forex market watchlist.
4. Hypothetical ROI Demo Dashboard.
5. Indicative agricultural price board for Mbeya Super rice and sembe.
6. Browser-only Practice Buy / Practice Sell simulation.
7. Youth Market Direction challenge with demo XP and a sample leaderboard.
8. Practice portfolio, local history generated by JavaScript, mobile bottom navigation and footer.

The audited `main` HTML does **not** contain a public elderly-assistance programme, humanitarian donation form, medical/education support application, CFG Games Hub, CFG BET catalogue, Quiz Pot, Plate Simulator, public KUZA CAPITAL page, agent referral programme, or live payment/investment checkout.

### 1.2 Important additional content exists outside main

The repository has open branches and PRs that contain additional declarations and modules. They are included below so they are not overlooked, but they are explicitly marked **not merged into main**:

- PR #8 — Global Impact & Opportunities: humanitarian/emergency, orphans/vulnerable children, elderly care, community development, agent/merchant/entrepreneur opportunities and a planned CFG programme allocation.
- PR #11 — CFG Games Hub, CFG PLAY, CFG PREDICT, CFG BET catalogue, Quiz Pot, Quiz question bank and Plate Simulator.
- PR #13 — KUZA CAPITAL informational page, productive-project concepts, illustrative calculator and future payment-method catalogue.
- PR #14 — Quiz Study Assistant server-side AI integration; Draft, based on the Games branch.
- PR #5 — authenticated Practice backend; Draft, with a live Supabase `practice-trade` Edge Function also found during this audit.

These are source-controlled proposals/preview implementations, not evidence that every page is deployed to the production homepage.

### 1.3 Database inspection limitation

The connected Supabase project `cashflow-gate` (`hddpramylgkqldwdomsa`) was listed as `ACTIVE_HEALTHY`, and an Edge Function named `practice-trade` was listed as ACTIVE with JWT verification enabled. However, attempts to list database tables and migration history terminated with connection timeouts. Therefore this audit **does not certify the current live database schema, rows, migration history, RPC body or financial balances**.

## 2. Classification and evidence rules

| Classification | Meaning in this register |
|---|---|
| Published on main | Present in the audited `main` source snapshot. This does not by itself prove current production deployment. |
| Implemented on unmerged branch / PR | Source code or page exists on a branch/PR, but is not part of audited `main`. |
| Approved design / planned | Documented product or programme direction; not necessarily implemented or active. |
| Proposed price / reference value | A planning or pricing reference, not a live fee, debit, FX conversion or payment. |
| Demo / simulation | Browser or illustrative behavior with no real financial settlement. |
| Active backend component | A deployed backend function reported ACTIVE by Supabase; this is not evidence of real-money functionality. |
| Unverified financial commitment | A displayed or documented figure whose actual approval, funding, issuance, distribution or reconciliation has not been established by the accessible evidence. |
| Historical / legacy reference | Preserved source value or prior design; not a current live offer or approved financial obligation. |

### 5.3 CFG PLATE GAMES — Plate / Drum Round

The PR #11 implementation shows 13 plates with equal probability:

- Each plate: **1/13 = 7.692307…%** (display rounded to 7.6923%).
- Normal: Plates 1, 2, 3, 7, 8, 11, 12 = **7/13 = 53.8462%**.
- Fail: Plates 5, 6, 10, 13 = **4/13 = 30.7692%**.
- Winning: Plates 4, 9 = **2/13 = 15.3846%**.
- Plate catalogue outcomes: Normal, Small Win, Big Win, Fail.
- Browser demo draw uses `crypto.getRandomValues` with rejection sampling in the PR branch code.
- No entry fee, stake, CFG wallet, payout, prize or cash reward is connected. The source explicitly says browser demo randomness is not production fairness certification.

**Probability inconsistency requiring canonical resolution:** the same PR branch's earlier Quiz/Plate design text contains a different weighting: Fail 63% (Plates 5, 6, 13), Winning 35% (Plates 4, 9), Plate 10 Fail 2%, and says the implementation must not draw until allocation rules are approved. The newer PR #11 implementation and PR description state equal 1/13 probability per plate and say the earlier weighting was changed with owner approval. This register records both source versions; do not treat either as permission for real-money play or payout. The product owner should ensure one canonical probability specification is retained before any future regulated activity.
